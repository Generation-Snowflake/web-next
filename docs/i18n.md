# Two languages (EN / TH)

- **URLs.** English stays at the unprefixed URLs (`/about`); Thai lives under
  `/th` (`/th/about`). Every page is rendered by `app/[lang]/…`.
  `proxy.ts` rewrites unprefixed requests to `/en/…` without changing the
  address bar. `/en/…` also works but its canonical is the unprefixed URL.
- **Switcher.** `LangSwitch` in `components/Navbar.tsx`: a plain link (full
  page load) to the same path in the other language.
- **Links.** Import `Link` from `@/components/i18n/Link`, never `next/link`.
  Write hrefs in English form (`/products/armo`); the component adds `/th` on
  Thai pages. `ButtonLink` already uses it.
- **Page copy.** Next to the component, as
  `const copy = { en: {…}, th: {…} } satisfies Record<Lang, …>`. Pages read
  the language with `await langFrom(params)` and pass `lang` down. Client
  components use `useLang()`.
- **Data** (`lib/products.ts`, `services.ts`, `training.ts`, `work.ts`,
  `site.ts`). The English file is the source of truth for everything,
  including prices, SKUs, images and links. Thai text lives in `lib/th/*.ts`
  as an overlay: objects merge by key, arrays merge item by item in the
  English order. Read data through the getters (`getProducts(lang)`,
  `getServices(lang)`, `getSite(lang)`…). When you add or reorder an item in
  an English array, update the Thai overlay in the same commit.
- **Metadata.** Use `alternates(path, lang)` for canonical + hreflang, and
  `ogLocale[lang]`. The sitemap lists both languages.
- **Typography.** Thai pages get `lang="th"` on `<html>`; `app/globals.css`
  relaxes line height and removes negative tracking for Thai headings.
- **Copy rules.** Plain, natural Thai for business and school readers, no
  ครับ/ค่ะ. Product names and technical terms (ROS 2, LeRobot, Scratch, MCP)
  stay in English.
